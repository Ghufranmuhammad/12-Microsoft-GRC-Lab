Purpose: Define how the GitHub portfolio should be organized and presented so that recruiters can quickly identify the strongest GRC work, understand the skills demonstrated, and distinguish major case studies from supporting learning materials.

---

1. Presentation Strategy

The GitHub portfolio should not be presented as a collection of every exercise completed during the GRC learning journey.

The goal is to make it easy for a recruiter to answer five questions quickly:

1. What GRC skills does the candidate have?
2. Which projects demonstrate those skills?
3. Can the candidate work with risk, controls, evidence, and compliance?
4. Does the candidate understand UAE-relevant cybersecurity requirements?
5. Can the candidate explain their work professionally?

The portfolio should therefore use a featured-project approach.

Presentation hierarchy

Tier 1 — Featured case studies

The strongest projects should receive the most presentation effort.

Tier 2 — Supporting framework projects

Useful projects that demonstrate additional framework knowledge.

Tier 3 — Supporting documentation

Notes, journals, exercises, and learning records that support the main portfolio but should not dominate the recruiter's first impression.

7. Spreadsheet Presentation Rule

Do not upload screenshots containing:

- Personal information
- Passwords
- API keys
- Real credentials
- Real company confidential information
- Private email addresses
- Sensitive personal data

All portfolio evidence should be fictional or appropriately sanitized.

Use filenames such as:

docs/images/risk-treatment-plan-preview.png
docs/images/soa-preview.png
docs/images/ecc-evidence-index-preview.png

Do not create dozens of screenshots.

Target: approximately 1–2 strong screenshots per major project.

10. Learning Journals vs Portfolio Evidence

Learning journals are useful, but they should not dominate the main recruiter-facing presentation.

For example:

learning/
    day20-journal.md
    day32-journal.md

can be kept as supporting material.

The README should instead direct recruiters toward:

Risk Assessment
Risk Treatment
Control Mapping
Evidence
Findings
Remediation

Rule:

Learning journal = proof of learning

Case study = proof of application

Both are useful, but the case study should receive greater prominence.
