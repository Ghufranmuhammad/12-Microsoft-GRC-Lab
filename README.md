# Microsoft GRC Lab

## Objective
To build a simulated Governance, Risk, and Compliance (GRC) workspace using Microsoft Purview and Compliance Manager for a fictional organization, DesertTech Solutions.

## Environment
* **Organization:** DesertTech Solutions
* **Platform:** Microsoft Purview Compliance Portal
* **Scope:** Multi-framework compliance assessment, evidence management, and audit log monitoring.

## Technologies
* Microsoft Purview Compliance Manager
* Microsoft Entra ID (Conditional Access & Access Reviews)
* Microsoft Purview Audit & eDiscovery

## GRC Capabilities Demonstrated
* Control mapping and gap analysis
* Quantifying compliance posture and risk reporting
* Designing structured evidence collection workflows
* Investigating security events using unified audit logs

## Compliance Assessment
Maintains an active assessment tracker mapping out 10 core improvement actions across access control, data governance, and operational security (located in `templates/compliance-manager-assessment.xlsx`).

## Evidence Management
Organized structural evidence folders complete with control specifications, required documentation types, and review frequencies across 10 distinct security domains (located in `evidence/`).

## Audit Log Use Cases
Simulates GRC use cases leveraging Microsoft Purview audit logs for privileged access tracking, account modifications, and security investigations (located in `docs/purview/audit-log-compliance-use-cases.md`).

## Key Findings
* Compliance scores reflect technical configuration progress rather than absolute risk immunity.
* Standardized evidence management significantly reduces manual friction during external audits.

## Skills Demonstrated
* Security framework interpretation and mapping
* Control implementation tracking and gap remediation
* Compliance reporting and risk communication for executive management

## Control Testing & Evidence Management
The lab demonstrates end-to-end GRC operations:
* **Control identification:** Mapping security requirements to a structured control library.
* **Evidence collection:** Building standardized evidence repositories and request lists.
* **Evidence evaluation:** Applying quality pillars (Relevance, Completeness, Authenticity, Accuracy, Timeliness, Traceability).
* **Control testing:** Executing realistic test procedures and documenting workpapers.
* **Findings:** Analyzing test results and identifying control gaps.
* **Remediation:** Formulating corrective action plans for failed controls.
* **Retesting:** Re-evaluating fixed controls to verify operational effectiveness.
* **Compliance mapping:** Tracing the complete GRC evidence chain from business risk to control closure.


## Disclaimer
This is a fictional/simulation project created for educational and portfolio purposes.
